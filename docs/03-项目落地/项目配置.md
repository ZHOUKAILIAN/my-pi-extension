# 项目配置

- 状态：`DECIDED`
- 层级：第三层

本文件说明 GitHub monorepo 的默认配置由谁拥有。配置定义项目如何承载产品，不定义产品本身的长期语义。

| 配置 | 责任 | 修改要求 |
| --- | --- | --- |
| `package.json` | workspace 范围、共享测试和类型检查命令、开发依赖 | package 或脚本变化时同步更新第三层 |
| `package-lock.json` | npm 依赖解析结果 | 依赖变化时由 npm 更新，不手工维护 |
| `packages/*/package.json` | package 名称、入口、依赖和 Pi manifest | 与 package 边界和源码入口保持一致 |
| `@pi/project-metrics` 与 `npm run metrics` | CLI-only 项目指标 contracts、Node client、Worker/D1 与命令入口 | 运行配置只经 `PI_METRICS_CONFIG` 指向本机私有文件；不在仓库放token或个人配置。`npm test` 与 `npm run test:agent` 删除测试子进程中的此变量，防止测试读取个人配置或访问真实目标。实现边界见 [L2 项目指标](../02-产品实现/项目指标-技术设计.md) |
| `tsconfig.json` | TypeScript 编译和类型检查默认值 | 编译边界变化时更新 |
| `.pi/workflow.json` | 可信项目下各 Node 的启动默认模型和 Skill 选择 | 不得包含 token、凭证或用户数据 |
| 项目 Skill / Project Knowledge | 当前仓库的目录、模块关系、领域术语、调查边界和验证命令 | 不改变 Workflow 状态机；必须能被 Worker 读取并在 Artifact/trace 中引用 |
| `.gitignore` | 生成物、依赖和本地状态的 Git 边界 | 新增本地或生成材料时先判断是否应进入正式层 |

## Pi 联用运行基线

项目选择 Pi SDK `1.1.0` 作为开发及 SDK Worker 基线：`@pi/workflow-runtime` 使用精确 `1.1.0` 运行依赖，根与相关 package 的开发依赖固定 `1.1.0`。Fast、Async 与 Fix 的 Pi host peer 范围按各自 manifest 声明；当前 Codex/Fix peer 为 `>=1.0.4 <1.2.0`，范围不等于该区间每个版本都已通过集成验证。已验证的宿主组合与边界由各 L2 owner 记录；不把 Pi `0.84.4` 视为新版日常入口兼容承诺。

SDK工厂由实际入口提供版本1的bundle，通用Runtime不依赖具体扩展。`@pi/fix` 目标optionalDependencies为 `@pi/codex-usage-status: 0.1.0`、`@pi/async-compaction: 0.1.0`；两个包须公开managed-factory导出。入口仅在创建Worker时动态加载并核对兼容，缺包/导入失败降级，未提供bundle报告inactive。隔离打包/omit optional/缺单包与双包均需验证，不只依赖workspace hoist。Worker必须从Runtime自有公共SDK入口解析1.1.0，不能受1.0.4宿主Jiti bare-import alias影响；需要时按公共exports解析到入口URL隔离加载，不深导私有模块。验收直接核对host-facing API和Worker执行SDK的版本/真实路径，不只检查manifest。

适配不修改用户全局 Pi 安装；不支持的旧宿主保留原模型/原生压缩路径并明确能力状态。依赖、公共 API 与实际宿主分别验证，peer 范围不替代运行证据。

## 本机功能开关

已确认的存储约定：复用本机当前用户的 Pi 全局 `<本机 agentDir>/settings.json`，默认 `~/.pi/agent/settings.json`。自研扩展本机偏好使用自定义命名空间 `myPiExtensions`，不新增偏好目录、独立状态扩展或共享状态 package。当前源码仍未适配此约定，差距见 [Fast](../02-产品实现/codex-usage-status-技术设计.md#6-l1-对应差距与未决项) 与 [Async](../02-产品实现/async-compaction-技术设计.md#91-全部-agent-目标的差距)。

在已有 settings 中增加或修改以下片段，保留其余原生配置字段；这里不是替换整个文件的模板：

```json
{
  "myPiExtensions": {
    "fast": false,
    "asyncCompaction": false
  }
}
```

| 全局字段 | 用途 | 缺省值 |
| --- | --- | --- |
| `myPiExtensions.fast` | 全部 Pi 主/子 Agent 的 Fast 请求意图 | `false` |
| `myPiExtensions.asyncCompaction` | 全部 Pi 主/子 Agent 的异步压缩意图 | `false` |

可信启动器使用内部 `PI_MY_EXTENSIONS_SETTINGS_FILE` 传同一绝对全局路径，CLI child 另用 `PI_MY_EXTENSIONS_AGENT_TYPE=subagent` 传有限分类；它们不是用户功能开关、不携带凭据。SDK Worker 采用单一loader/runtime的会话factory闭包参数，不使用自定义宿主启动事件字段，也不在执行中修改进程全局环境。具体 loader、fence 和来源协议由对应 L2 拥有。

字段只接受 JSON 布尔值，不把字符串 `"false"` 当作开关。后续自研扩展的本机偏好可在此命名空间下分别拥有字段；第三方扩展、项目配置、凭据、Session、outbox 和 metrics 私有配置沿用各自 owner，不自动迁移到这里。

这是本仓库自定义字段，不是 Pi 内置 Fast/Async 设置 API；仅增加 JSON 字段不会自动安装、加载或启用尚未适配的扩展。`compaction.enabled` 仍是 Pi 原生自动压缩设置，不等同于 `myPiExtensions.asyncCompaction`。

所有主/子 Agent 必须使用同一个本机全局文件；项目 `.pi/settings.json`、child 临时 agentDir 或 Session 不能产生另一套功能开关。机器级路径由入口统一解析并沿调用链传递，不能仅从子 Agent 的临时目录推导。测试须显式指向共同的临时全局设置，不读写真实个人文件。

产品命令仅保留 `/fast`（无参数切换）、`/fast on|off` 和 `/async-compact on|off`；显式 `/fast toggle`、`/fast status` 不属于支持范围。命令与用户手动编辑同一全局字段。已运行 Agent 在下一模型请求、后台压缩调度或候选采用前刷新适用字段，不等用户再次输入，也不要求重启；已发出的请求不追溯改写，候选接入前仍核对关闭状态。另一台电脑独立设置。

读写逻辑分别归两个既有扩展，必须协调宿主文件锁、保留其他原生及扩展字段，不改用户默认模型或权限。读失败/值无效时 Fast 不发 priority、Async 走原生路径；保存失败不改持久真值、不冒称全机成功，正常工作继续。`myPiExtensions` 不保存密钥，也不代替 `PI_METRICS_CONFIG` 的采集许可。

## GitHub 固定版本安装

GitHub Release 使用 monorepo Tag `v0.1.0`，不向 npm 发布 `@pi/*`。根 `package.json` 的 Pi manifest 是日常安装入口，仅声明 `/fix`、`/fast` 和 `subagent`；各子 package 保留独立入口，根入口不加载异步压缩、恢复 fence 或服务端 Worker。

```bash
pi install git:github.com/ZHOUKAILIAN/my-pi-extension@v0.1.0
```

Pi 在自己的 Git package 目录安装该 Tag 和生产 workspace 依赖，不引用开发 worktree。替换已有本地安装时，先备份个人 settings，再移除三个旧本地 package 声明，避免重复注册；不删除原源码或运行数据。随后 `/reload` 或重启 Pi。固定 Tag 不跟随 `main`，升级或回退需明确选择另一个版本，并重新加载。替换版本不能回退已经写出的 Session/WAL 数据格式。

需要只启用某个入口时，在同一 Git package 的资源过滤中选择对应的 manifest 路径，例如：

```json
{
  "source": "git:github.com/ZHOUKAILIAN/my-pi-extension@v0.1.0",
  "extensions": ["packages/codex-usage-status/src/index.ts"],
  "skills": [],
  "prompts": [],
  "themes": []
}
```

固定 Tag `v0.1.0` 的历史三扩展加载验证宿主为 Pi `1.0.4`；Tag 不随当前分支变化，不包含尚未发布的候选功能。`scripts/release-install.test.ts` 验证当前源码与 lockfile，而非下载该 Tag：在临时目录安装生产依赖，使用真实 Pi `1.0.4`、`1.1.0` loader/runner 核验命令、工具、无 Worker 的导航及退出。两版 smoke 已执行；未配置相应宿主路径的运行会跳过，不能作为该版本的通过证据。Workflow Runtime 的精确 `1.1.0` SDK/AI/TUI 生产依赖与 Fix 的宿主 peer 分开检查；安装加载通过不证明真实 Worker 解析隔离。真实 provider 和交互式长流程的验证边界由各 L2 owner 维护。异步压缩仍按独立隔离入口试用，不因进入 Git Tag 就自动启用。安装不会创建指标私有配置或开启远端采集。

## 项目指标本地安装与采集

`@pi/project-metrics` 随 monorepo 工作区提供，不是可单独自动发现的 Pi 扩展。Fast/Async 加载它的 Node client；`npm run metrics` 是独立 CLI。使用包含本功能的 revision 后，在仓库根目录执行：

```bash
npm ci --ignore-scripts
```

本地 Pi package 不会替你安装工作区依赖，不能跳过此步或假设 `@pi/project-metrics` 已发布到 npm。两种扩展的宿主范围由下文[Pi package 依赖安排](#pi-package-依赖安排)拥有；不要为了启用采集升级整个日常 Pi 或联合加载不兼容扩展。

### 私有配置

先准备本人已经部署的 Worker/D1、与 `TARGET_NAMESPACE` 和 D1 元数据一致的 namespace，以及独立读、写 Token。Wrangler 管理登录不是上报或查询凭据。配置只从环境变量读取：

```bash
export PI_METRICS_CONFIG="$HOME/.pi/agent/project-metrics/config.json"
```

此目录和待投递目录使用 `0700`，配置和两份 Token 文件使用 `0600`；路径不能经过符号链接。将 Token 值分别保存到私有文件，不放进配置正文、shell 参数、命令历史或 Git。配置示例中的值须替换为自己的部署数据和**绝对路径**；JSON 不展开 `$HOME` 或 `~`：

```json
{
  "enabled": true,
  "endpoint": "https://YOUR-WORKER.YOUR-SUBDOMAIN.workers.dev",
  "namespace": "YOUR-DEPLOYMENT-NAMESPACE",
  "dataset": "live",
  "writeTokenFile": "/absolute/private/project-metrics/write-token",
  "readTokenFile": "/absolute/private/project-metrics/read-token",
  "outboxDir": "/absolute/private/project-metrics/outbox"
}
```

`endpoint` 是 Worker 的 HTTPS 根地址，不含用户名、query 或 fragment。`namespace` 不是 CF 账号 ID，必须匹配自己的部署；不能复制其他人的配置。队列在创建时绑定 endpoint/namespace/dataset，改配置不会把旧队列迁到新账号。Worker/D1 合同及当前验证边界见[项目指标实现](../02-产品实现/项目指标-技术设计.md)。个人部署配置、凭据与运行数据不在本仓库分发。

`enabled: true` 是这台机器的明确采集许可；可在自己的 shell 启动配置或专用启动器里设置 `PI_METRICS_CONFIG`，使后续 Pi 进程继承。仓库不修改 shell 或 Pi 个人配置。没有环境变量或设为 false 时不远端采集；CLI 在 false 下仍可查询。

### 加载本地扩展

推荐先单次显式加载，不写入个人 settings。Fast 使用根 lockfile 对应的宿主：

```bash
./node_modules/.bin/pi --no-extensions -e ./packages/codex-usage-status/src/index.ts
# /fast on：从 Off 真正变 On 才记录；重复 on 不新增
```

Async 使用匹配宿主的隔离主 TUI：

```bash
node ./packages/async-compaction/node_modules/@earendil-works/pi-coding-agent/dist/cli.js \
  --no-extensions -e ./packages/async-compaction/src/index.ts
# 首次 /async-compact on 保存本机偏好；阶段事件在实际发生后产生
```

先 `export PI_METRICS_CONFIG` 再执行对应命令。加载即让采集处于就绪状态，不单独发送启动打点；功能开关读取独立的本机偏好，采集配置不替用户开启它们。无实际事件时不上传；已保存未确认的队列可由后续事件触发有界投递，或手动 `npm run metrics -- flush` 补报，不扫描历史 Session 或开启记录。

若使用兼容 Fast 的个人 Pi profile，可用同版本 Pi 注册本地目录：

```bash
./node_modules/.bin/pi install "$PWD/packages/codex-usage-status"
```

这会修改个人 `~/.pi/agent/settings.json` 的 package 声明；本地源码目录不被复制，移动或删除工作区会使声明失效，已有全局扩展也需与所用宿主兼容。Async 仍只按上面的显式隔离入口运行，不注册到普通混合加载 profile。日常三扩展的固定版本安装使用上文 GitHub Release 入口；异步压缩不在该入口的加载清单中。更改源码后重新启动对应 Pi 或按其资源重载规则加载；仅修改配置不会给旧进程补上缺失的环境变量。

### CLI 与页面

在仓库根目录、带相同环境变量运行 `npm run metrics -- status|stats|flush`；`stats` 默认 live，可加 `--days 1..31` 和 `--validation`。查询只表示云端已接收数据；本机 pending/failed/unknown 不是完整使用量证明。`flush` 只补报本配置目标的私有待投递队列。

当前没有项目指标网页。业务趋势图需由前端读取授权 API 后绘制；CF 内建运维图见 [Workers metrics](https://developers.cloudflare.com/workers/observability/metrics-and-analytics/) 和 [D1 metrics](https://developers.cloudflare.com/d1/observability/metrics-analytics/)，不等于 Fast 次数或压缩阶段业务图。

## Node 测试摘要

`scripts/test-suite.mjs` 是 npm test 与 Agent 摘要共用的 Node 测试范围和 Node 参数 owner。它收集 `packages/*/test/*.test.ts` 与 `scripts/*.test.ts`；`npm test` 保留原生 runner 的完整输出，Agent 推荐运行 `npm run test:agent`。项目适配将完整发现范围、共享 Node 参数和用户附加文件交给 [`node-test-brief`](https://github.com/ZHOUKAILIAN/node-test-brief) CLI，并显式启用严格 Git 快照、拒绝不支持的参数及 `pretest`/`posttest` hooks。执行、事件报告、日志、校验与取消由 SDK 拥有；接口与行为细节见 [SDK README](https://github.com/ZHOUKAILIAN/node-test-brief#javascript-api)。固定 archive 依赖来源由根 `package.json` 与 `package-lock.json` 唯一记录。

```bash
npm run test:agent
npm run test:agent -- --timeout 90s
npm run test:agent -- --help
```

SDK CLI 的参数、默认超时、摘要、日志格式与清理行为以 SDK README 和实现为准；本项目只负责选择完整测试范围及 Node 参数，并在适配层固定 Git 快照与 npm hook 政策。该入口不加载 Pi provider 或用户业务数据。

`npm test` 是保留完整输出的交互入口。两种命令共用 `scripts/test-suite.mjs` 的发现范围；新增 `scripts/*.test.ts` 自测与 package 测试都进入完整套件。

## 云端 AI 检查

GitHub-hosted Runner 使用 Node 24。[独立工具 manifest](../../.github/ai/package.json)及 lockfile 固定 Pi 1.0.4 运行时，不改变产品 package 的宿主范围。安装使用 `npm ci --ignore-scripts --prefix .github/ai`，不在安装步骤提供模型或凭据回存 token。

| 配置 | 值与用途 |
| --- | --- |
| 模型 | 精确 `openai-codex/gpt-6-astra`；不可用时阻塞，不 fuzzy 匹配或 fallback |
| GitHub Environment | `ai-review`；部署分支策略应只允许 `main`，不向 PR head 分支开放凭据 |
| `PI_CI_AUTH_JSON` | Environment secret；专用 Pi 登录的单一 `openai-codex` OAuth 对象，含 `type`、`access`、`refresh`、`expires`、`accountId`；不含其他 provider |
| `CI_ENVIRONMENT_TOKEN` | Environment secret；单独 fine-grained PAT，仅选本仓库及 Environment secret 回存所需的 Environments 读写权限；不使用日常 `gh` token |
| 状态回写 | 使用作业 `GITHUB_TOKEN` 的 statuses 写权限，模型子进程不取得它或凭据回存 PAT |

Environment secret 在作业开始读取，避免 repository secret 在工作流排队时就取得旧快照。AI 工作流全局串行，独立登录凭据不得与本机日常 Session 共用刷新链。凭据临时目录为 `0700`、文件为 `0600`；回存通过 `gh secret set` 的 stdin，不把明文放进命令参数、缓存或 artifact。触发资格、结果合同、门禁及未验收项由 [L4 云端检查](../04-仓库治理/GitHub维护流程.md#github-云端检查与授权)拥有。

### 专用凭据配置

1. 在 GitHub 创建 `ai-review` Environment，并将部署分支限制为 `main`。生成仅选本仓库、具备上述权限且有合理到期时间的专用 fine-grained PAT；在终端安全提示中配置，不发到聊天或提交：

```bash
gh secret set CI_ENVIRONMENT_TOKEN --repo ZHOUKAILIAN/my-pi-extension --env ai-review
```

2. 在仓库外的独立私有目录启动 Pi 1.0.4，完成一次 `/login openai-codex` 后退出；只登录该 provider。不要复制日常 `~/.pi/agent/auth.json`：

```bash
mkdir -p "$HOME/.pi/ci-my-pi-extension"
chmod 700 "$HOME/.pi/ci-my-pi-extension"
cd "$HOME/.pi/ci-my-pi-extension"
PI_CODING_AGENT_DIR="$PWD" pi --no-extensions --no-skills --no-prompt-templates --no-context-files --no-mcp
```

3. 将该目录中生成的专用凭据通过 stdin 加密上传：

```bash
gh secret set PI_CI_AUTH_JSON --repo ZHOUKAILIAN/my-pi-extension --env ai-review \
  < "$HOME/.pi/ci-my-pi-extension/auth.json"
```

上传后不要再用此本地目录调用模型或刷新登录；云端刷新后的凭据由 Environment 持有，本地副本会过期。重新播种应重新完成独立登录，不与正在运行的云端作业争用刷新链。账号可用性、模型权限和 PAT 到期仍需维护；初次配置完成后按 L4 启用条件实测，而不是仅凭 secret 名称存在判为成功。

公开 Step Summary 通过统一投影过滤常见凭据样式、显式 credential 键值及控制器已知密钥，再转义 HTML 和工作流命令。它不是通用业务隐私识别器：PR/Issue 不得粘贴凭据或私有现场材料，原始源正文与模型输出不直接进入日志或 artifact。

## Pi package 依赖安排

`@pi/codex-usage-status` 遵循 Pi core package 例外：Pi 宿主提供 `@earendil-works/pi-ai`、`@earendil-works/pi-coding-agent` 和 `@earendil-works/pi-tui` 运行时实例，因此它们在该 package 的 `peerDependencies` 中声明，不转为 runtime `dependencies`、不打包。当前 peer 范围为 `>=1.0.4 <1.2.0`，开发依赖固定 `1.1.0`；项目选定的 SDK 基线为 `1.1.0`。Pi `1.0.4`、`1.1.0` 有临时安装目录下的真实 loader/runner smoke 验证，包含新增运行依赖与本机开关；但 peer 范围不表示所有 1.0.4–1.1.x 版本均已端到端验证，也不承诺 0.84.4 的新版功能兼容。具体差距见 [L2](../02-产品实现/codex-usage-status-技术设计.md#5-验证入口与当前边界)。

第三方运行时依赖如未来增加，才按 Pi package 规则进入 `dependencies`（必要时随包打包）。依赖关系以各 package `package.json` manifest 和 `package-lock.json` 的解析结果为权威，本文只记录项目默认安排，不替代 manifest/lock。

`@pi/fix` 的 Pi AI/SDK/TUI 由宿主提供并声明为 peer；开发依赖固定 `1.1.0`，不把 Pi TUI 旧固定运行时副本加回生产依赖，避免混用宿主与安装副本的组件。当前源码在 Pi `1.0.4`、`1.1.0` 的生产依赖加载 smoke 不等于真实 Worker/TUI 全流程验收，也不代表已更新固定发布 Tag。

`@pi/async-compaction` 独立声明 Pi core peer `>=1.0.4 <1.2.0`，开发依赖固定 1.1.0 并在 package 内单独解析。1.0.4/1.1.0 均通过隔离类型检查和合成 SDK threshold、原生 fallback、文件接续及 JSONL 恢复测试。运行时仅允许显式 `pi --no-extensions -e ./packages/async-compaction/src/index.ts` 的单入口主 TUI profile；peer range 不是逐版本集成验收。

`@pi/subagent` 的 Pi 依赖独立升级，不代表整个 monorepo 的宿主支持范围一起改变：

| 配置/证据 | 当前值与限制 |
| --- | --- |
| `pi-ai`、`pi-coding-agent`、`pi-tui` peer | `>=1.0.4 <1.2.0`；覆盖 Pi 1.0.4 与 1.1.x，不扩大到未来 minor。 |
| 同三项 dev 依赖 | 固定 `1.1.0`，lockfile 为 subagent 单独解析；以各 package manifest 声明的 peer 范围为宿主约束。 |
| 直接验证版本 | 1.0.4 与 1.1.0 的真实隔离 headless 流、工具事件/会话续接和确定性协议回归；协议矩阵区分两版共有字段与 1.1.x 的 `durationMs`，并对嵌套消息及 tool event 做 family 一致性校验；1.1.x 其他 patch 未逐个做真实 E2E。验证边界见 [L2](../02-产品实现/subagent-dispatcher-技术设计.md#81-pi-104-与-11x-协议与验证边界)。 |
| 升级与回退 | 严格协议校验必须与新宿主同步更新，不能只改版本号；更改源码后需 `/reload` 或新 Pi 会话生效。不自动解除历史 quarantine 或重跑历史任务；回退也不承诺改写已生成的新版本 session。 |

Subagent 的 `package.json` 使用 Pi manifest 的 `pi.extensions` 声明普通宿主自动加载入口；side-effect fence interceptor 单独声明在非自动发现的 `pi.recoveryFenceExtensions` 中，并固定 `role: "fence"`。该字段只供恢复 fence 的显式快照校验使用，不会让 Pi 普通 package loader 自动加载 interceptor；快照 provenance 必须保留并验证两组 entry 声明。

## Workflow 项目配置

`.pi/workflow.json` 是项目共享的 Workflow 执行选择，不是第五层 session 状态。Pi 只在项目受信任时读取它。文件可以选择各 Node 的启动默认模型和 Skill；模型和 Skill 名称可以进入 Git 历史，但账号凭证、环境密钥和个人数据不得写入该文件。

项目配置不能修改 Workflow 的整体流程、Stage、Node 归属、Transition、Guard、Review 最低门禁、工具能力边界或 Acceptance 最低条件。Skill 可以提供项目特有的调查方法、验证清单、验收证据格式和命令，但不能单独授权流转或宣称 Run 已完成。

Runtime 内置 Workflow Definition 和默认策略；`.pi/workflow.json` 未声明的 Node 使用 Runtime Defaults。当前源码已优先读取 `.pi/workflow.json`，不存在时兼容读取迁移前的 `.pi/workflow-models.json`；移除旧格式前需同步更新 parser、测试和迁移说明。

`.pi/workflow.json` 的 Node `model` 是启动该 Worker 的项目默认模型，不是第一版的候选 allowlist。Workflow 执行期间用户通过原对话中的当前 Worker 模型选择器切换模型，属于该 Worker Session 的 Run 级实际执行选择；候选来自 Pi scoped/available 已认证模型并满足 Worker 兼容约束，不回写 `.pi/workflow.json`，也不改变主 Session或后续 Node 的项目默认模型。Runtime 必须保留 Effective Policy 与实际模型变化的区别；只有用户明确采纳新的项目默认后，才更新第三层配置。

用户补充信息、Run Control WAL、Worker Session 文件、逐条投递事件和连续补充版本属于 Run/session 状态，不进入 `.pi/workflow.json` 或项目目录；目标位置是 Pi agent 本地状态根目录下由 Extension 管理、权限受控的 Run 子目录，生命周期按第五层边界管理。

Runtime 第一版 sidecar 默认：每个 Run 最多 20 个 Worker attempt；intermediate Worker/UI 原文在 Run settled 30 天后到期；无 live lease 的 unfinished Run 从最后 durable event起保留 30 天；parent 缺失的 settled Run从首次观察起最多再保留 7 天，取更早删除期限。它们是仓库级运行默认，不写入项目 `.pi/workflow.json`；修改默认值必须同步 L2 保留/GC 测试和 L5 数据边界。

根项目开发依赖和锁文件使用 Pi SDK `1.1.0`；`@pi/codex-usage-status` 的宿主范围由上方 Pi package 依赖安排维护。Child Session 使用独立内存 SettingsManager，具体 SDK API 以选定版本及对应契约测试为准。若未来改变最低 Pi 版本，必须同步 package/lockfile、第三层兼容说明和第四层验证证据。

实验性的模型、Skill 或运行参数在明确采纳前只放本地第五层。采纳后再更新 `.pi/workflow.json` 和对应 L2 测试；只有当产品允许的能力、隔离承诺或行为语义发生变化时，才更新受影响的 L1 owner。

## Workflow 与项目语境

Workflow Runtime 只提供通用的状态、交接、恢复、Guard 和审计机制，不拥有 Feature/Fix 的业务流程，也不假设当前项目一定有前端、后端、数据库或特定外部服务。项目应通过 Skill、Project Knowledge 和项目策略提供这些语境：

- 当前仓库包含哪些模块、调用方和被调用方；
- 某类问题需要沿哪些影响面调查；
- 哪些证据、测试命令和业务不变量才足以形成结论；
- 哪些范围无法访问或尚未验证。

Skill/项目知识负责定义方法和标准，Worker 负责执行并提交结果，Runtime 负责把实际工具事件、Artifact、未验证项、状态迁移和 Guard 决策持久化为可审计记录。不能因为模型加载了 Skill，就把 Skill 中的“应检查”视为已经检查；必须有工具事实或结构化 Artifact 证据。
