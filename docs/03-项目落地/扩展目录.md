## 已确认落地边界

1. Feature 和 Fix 是两个顶层 Workflow Extension 产品边界。
2. 每个顶层入口目标上对应独立 Pi package，保持在同一个 Git monorepo。
3. 两个入口共享 `workflow-runtime` 和 `workflow-contracts` 普通 TypeScript libraries。
4. 顶层 package 拥有命令接线及自己的可执行 Workflow Definition。
5. Node 默认是 package 内的普通 Definition；只有出现独立安装、生命周期、环境或发布需求时才重新评审。
6. 命令、package 名或目录迁移不得破坏已有 session/checkpoint，兼容策略应在 L2/L3 变更时明确。
7. Fix 第一版的运行中协作不新增 tmux package、独立子窗口或普通用户控制命令：`@pi/fix` 继续拥有 `/fix` 与 Pi UI 接线，`workflow-runtime` 提供可复用的 Worker Session 控制机制；是否抽取独立 Workflow UI package 仍待后续评审。

当前实现与目标产品契约的完整差异见[第二层实现地图](../02-产品实现/README.md#已知-l1--l2-drift)。
