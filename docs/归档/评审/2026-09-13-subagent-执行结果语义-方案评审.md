## 目标规则（待独立评审）

| 情况 | 执行语义与反馈 | 自动重试/切模型 |
| --- | --- | --- |
| 完整有效协议、退出码 0、最终助手 stop | “已返回”；有过程工具错误时附数量/有界诊断，不隐藏最终报告 | 无 |
| Agent 正常返回一份测试失败或业务阻塞报告 | 同样是“已返回”，报告与工具异常完整交给主 Agent；不代表任务目标或验收通过 | 不因工具/测试失败自动重试或切模型 |
| 最终 provider error | 当前终止诊断；此前工具错误不能覆盖 provider 错误分类 | 保留现有闭集瞬态白名单与每模型初始+2预算；非瞬态不切换 |
| 进程异常、signal exit、协议损坏、缺有效终态 | 执行失败/未知传输，fail closed；有报告文本也不能掩盖异常 | 不扩大白名单 |
| 用户取消或最终 aborted | 显示取消，不画成功勾 | 不重试 |
| 最终 length | 明确未完成/长度截断，不冒充正常返回 | 不重试；持久会话允许明确继续 |
| 仍在执行的 progress | 显示执行中，不用初始化的 unknown failure 画最终红叉 | 不改变执行控制 |

- 不增加新的 Worker Artifact、完成 JSON 协议、自然语言成功分类器或大型共享 runtime。
- 保留现有 execution success/status 的兼容含义，并在 API/文档明确它只表示 child 正常返回；若需增量字段/枚举，必须检查 sanitizer、dispatcher、registry validator、metadata、UI 和历史记录兼容，不为 UI 独立造一套状态。
- 过程诊断保留类型、数量和可追溯安全引用；原始 token、header、工具 payload、task/prompt、机器路径不进入新增 DTO。有界详情截断不能让异常总数变成零；不推断任何单个工具异常已被修复。
- 最终返回内容必须保留助手报告，不再仅以旧错误替代；机器字段和用户文案均不得声称验收通过。
- single/parallel/chain 都遵循执行状态，不因工具尝试错误自动停止正常返回的链；继续只表示传递上一步报告，不表示验收授权。需要验收或写操作授权的下游仍由主 Agent/独立治理控制；警告需保留在返回详情及必要的交接提示中。
- 不改变模型默认值、fallback 列表、权限、工作树、真实运行配置，也不修 weekly-review 分支。模型仍由现有配置选择，实现使用 luna、代码评审使用 terra；不擅自覆盖模型。
- 普通命令的非零返回码仍如实保留；不全局吞错误、不把任意非零改成成功。`git diff --no-index` 这类命令由调用方按其退出语义解释，dispatcher 不猜命令成功。

## R2：固定的状态与终态映射（待复核）

本节细化上面的目标，不改变“不加验收协议”的边界。`FailureKind` 继续是唯一执行结果分类；新增 `incomplete` 表达长度截断，不新增另一套 execution status 枚举。`DispatchResult.status` 是现有会话恢复状态的投影，不承载验收。

| 情况 | failureKind | dispatch status | registry | 文案 / tool isError / chain |
| --- | --- | --- | --- | --- |
| 正常最终 stop、退出 0 | success | completed | settled | 已返回 / false / 传递报告和诊断，继续 |
| 最终 length、退出 0 | incomplete | 持久 recoverable_failed；临时 failed | 持久 failed | 输出截断，未完整返回 / true / 停止 |
| 本地取消；或协议/进程完整性检查通过后的最终 aborted（非本地取消的 signal close 优先归 unknown_transport） | cancelled | cancelled | cancelled | 已取消 / true / 停止 |
| 最终 provider error | transient_provider 或 non_transient_provider | 沿用 dispatcher 现有 retry/耗尽/失败映射 | 沿用现有对应映射 | 执行失败或重试中 / 最终 true / 停止 |
| 信号退出、协议失败、缺终态、stop/length 非零退出 | unknown_transport | 持久 recoverable_failed；临时 failed | 持久 failed | 执行失败，明确原因 / true / 停止 |
| 历史或注入 runner 的 task_failure | task_failure（兼容读取，本 runner 不再由工具事件产生） | 沿用现有非重试失败映射 | failed | 旧任务失败 / true / 停止；不得回写为成功 |

- 当前 attempt 在 close 完成分类前，`AttemptResult.phase=running`；完成分类后为 `finished`。phase 是运行生命周期，不是第二套执行结果；dispatcher 的 progress 不得伪造终态 failed。UI 优先展示 running；缺 phase 的旧终态按旧结果读取，Pi render 的 isPartial 可用于旧 progress 兜底。
- 当前 attempt 增加可选 `diagnostics: { toolErrorCount, providerErrorCount }`，新 runner 始终产生非负安全整数。工具计数按本 attempt 的 tool_execution_end 统计，与保留详情的上限无关；历史 provider 错误按本 attempt 完成的 assistant error 消息计数。不把失败是否被业务解决写入计数。
- sanitizer 对两个计数严格白名单投影；registry attempt 摘要、parent metadata 和 tool details 同步保留可选 diagnostics。缺字段的旧记录仍合法，缺失表示未提供统计，不能声称异常为零。phase 不写 registry，registry 只保存终态；incomplete 纳入严格枚举兼容校验，不修改旧记录。
- 工具详情沿用现有脱敏 toolResults 和引用；provider 历史诊断沿用脱敏 assistant 消息，绝不将原始 stderr/status/tool payload 引入新 DTO。新增计数不替代已有详情，截断不能清零计数。

### 当前 attempt 的裁决顺序

| 优先级 | 确定性规则 |
| --- | --- |
| 1 | 当前调用收到本地 abort signal：cancelled，不重试 |
| 2 | spawn/流式 JSON/header/身份校验失败、空输出、非空畸形记录、signal close(code=null)、没有当前有效最终助手候选：unknown_transport，不重试 |
| 3 | 当前最终助手 aborted：cancelled，不重试 |
| 4 | 当前最终助手 error：只用该消息自身的类型化 status/errorMessage 归类；有效 provider error 允许 Pi 返回非零退出码，仍保持 provider 分类与闭集 retry；禁止读取旧工具 status、旧 errorMessage 或游离 stderr 作为 retry 依据 |
| 5 | 其余 stop/length 但进程非零退出：unknown_transport，不重试 |
| 6 | 当前最终 length：incomplete，不自动重试 |
| 7 | 当前最终 stop 且正常退出：success；最终 errorMessage 清空；过程诊断保留 |

当前有效最终助手候选只属于最新消息周期：后续 assistant message_start、assistant message_end(toolUse) 或新 tool_execution_start/end 使旧候选失效，直到新的有效 assistant message_end(stop/error/aborted/length) 才重新建立；turn_end/agent_end 的常规尾事件不清除候选。同 attempt 可以 error 后重试并出现新的 stop，最终按新的 stop 归类。没有新的终态就不得复用旧 stop/error。每个新 attempt 都重新初始化；provider 分类状态仅从最终 error 自身取得，消息自身无类型化 status 时只解析该 errorMessage；不从任意其他事件提取 HTTP status。最终异常文本采用当前终止原因的安全固定分类，正常返回不保留旧最终 errorMessage。

### Chain 与聚合口径

- chain 只因非正常执行（failureKind 非 success）停止。正常返回的业务失败报告不是自动验收授权；下一步读取报告并自行遵守已有授权与验收要求，不得因为工具 isError=false 就执行超范围写入。
- `{previous}` 固定为上一步最终助手文本，追加由 dispatcher 生成的独立段落：`[执行诊断：已返回不代表验收通过；工具异常 N；模型异常 M]`。缺计数的旧结果标未提供，不编造 0。该提示只含计数、不含 tool payload、机器路径或秘密。即使下游模板未使用 `{previous}`，chain 也须在任务尾部追加该执行诊断段，防止异常提示被丢弃；正常最终文本的既有插值行为不变。
- parallel 的统计文案统一为“已返回 N/M”，不是 succeeded 或通过；警告单独显示，各任务最终报告保留。single/chain 正常返回统一“已返回”，不得宣称任务或验收成功。
- 正常返回的 tool content 首先保留助手报告，附执行诊断摘要；非正常返回也保留已捕获报告并明确未完整返回，不能只有 `(no output)` 或旧错误。tool isError 和 chain stop 仍由 failureKind 决定。
