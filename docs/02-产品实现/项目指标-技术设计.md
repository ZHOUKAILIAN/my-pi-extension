# 个人 CF 项目指标实现

产品合同由 [L1 项目指标](../01-产品定义/项目指标.md)拥有。当前实现包括 contracts、Node client、Fast/Async producer 接缝、CLI、Worker/D1 统计及离线测试。同一 CF Worker/D1 已部署私有 CLI 接口，鉴权及基础部署检查通过；受控真实 Fast/Async 来源、幂等 ACK 及独立 CLI/D1 统计一致性已核验；验证范围和未覆盖项集中在下表。本机默认无采集配置时关闭，日常采集未启用。

## 运行链

- `@pi/project-metrics/contracts` 是不依赖 Node 的事件规范化和 canonical JSON 实现；Node target/event hash 使用 Node crypto，Worker payload hash 使用 Web Crypto。事件严格限制三类白名单、UTC 时间、字段及值。事件ID全局 UUID；Fast 不含耗时字段，Async 耗时 unknown 必须有有限原因。
- Fast 在用户实际 Off→On 分支同步捕获不可变的 eventId/occurredAt，并登记最多32个未完成任务；下一调度回合才排他写本地开启记录，成功后将同一事实交给 client。本地写、入队及网络均不在命令 await 链上；超额或失败只标采集不完整，不回滚 Fast、不覆盖原业务异常。安全提示仅由仍活跃的原作用域发出。
- Async `Timing.finish` 保留原本地 `appendEntry`，随后独立安全提交相同终态至 client，hook 不等待项目传输。UUID 失败不生成远端替代ID；旧 scope、重复 finish 不重复投递。`session_shutdown` 关闭该 producer 的网络作用域，Fast 本地record与项目outbox共用一个至多一秒墙钟 drain；Async 本地drain也至多一秒，均不等待网络。关闭后的本地提交仍可保留在outbox，但不会由旧作用域发起上传。
- Node client 仅由 `PI_METRICS_CONFIG` 指向配置；未设置或 `enabled=false` 时 producer 不读取 token、不联网、不创建 outbox。配置/凭据和outbox拒绝符号链接、非私有文件权限及非自有路径；目标 hash 分隔 endpoint、namespace、dataset；target 子目录保存不可变 envelope。outbox 单条16KiB、总量512条、进程内队列32条、flush批次16条。PID/nonce文件锁只覆盖本地操作，等待有界；死PID锁仅在同目录排他reaper协调内重新确认PID、inode和nonce后删除并尝试发布新锁。普通发布仍用排他link竞争；未知或遗留的reaper guard不自动回收，后续涉及死锁回收的操作有界拒绝。网络不持锁。
- HTTP仅发单条POST，禁止重定向，整体请求/ACK deadline五秒、ACK最多2KiB；只读 CLI stats GET 的 headers、有限body与响应校验共用五秒逻辑截止，忽略abort的传输/reader也不能无限挂住 CLI。即使fetch或ACK reader不响应abort，截止也使逻辑flush结束、保留未知outbox并释放槽位；作用域关闭取消在途请求并隔离旧ACK，新作用域及CLI可显式重试。Fast在成功`session_tree`后旋转作用域；Fast的可取消`session_before_*`不关闭该作用域。收到非2xx headers即中止传输并尽力取消未读取的body，不等待可能未结算的取消Promise；ACK读取失败或超限也取消reader，迟到的孤立响应直接丢弃并释放。仅仍有效尝试的同ID accepted/duplicate删除本地记录。永久4xx（408/425/429除外）按HTTP状态用私有标记跳过自动重试，先越过标记再取每批16条；`flush --retry-failed`是显式有界重试入口。其他失败和未知ACK保留队列。`status`按target/dataset暴露可知 pending/failed；无法归属的本机错误只标unknown，不嫁接到另一目标的failed。
- Worker位于 `packages/project-metrics/src/worker.ts`，提供健康检查、POST项目事件、GET聚合统计；未提供网页或公开明细。Worker校验读写secret均存在且互异、按role鉴权，核对配置与`project_metrics_meta` namespace；D1写通过唯一event_id和同一SQL中的跨dataset日配额判定实现去重/限额。0003 migration已在原CF D1执行，仅增加项目指标表、元数据及索引，namespace已初始化并核对。
- Stats先在一次D1读取中捕获ingest水位与asOf，所有返回行同时受水位、接收时间约束。API只返回`received_only`聚合；按UTC发生日计算最近完整日、前一基准日、总体及模型分组均值/已知样本/unknown；基数为零或缺失、环比运算溢出非有限时标为不可比较，有限的大环比仍可经CLI读取；今天按接收日单独列示、不参与完整日比较；发生时间为null的样本也按接收日独立分组。结果有行数上限及`truncated`标记。CLI可通过`--days`和`--validation`选择范围，严格解析远端统计字段/类型并拒绝凭据回显，再附本机同target队列及缺口状态。失败仅输出固定类别（超时、传输、鉴权、HTTP、响应无效、超量、配置）或通用提示，不回显原异常、响应、URL或凭据；错误响应/超限响应中止传输并尽力取消未读body，不等待可能未结算的取消。

## 本机开关与 Agent 来源接线设计（REVIEWING）

用户已确认子 Agent 的后台生成与受支持 threshold 前台阶段可上报。目标扩充来源分类及统计，不增加事件 kind，不改变许可、Token、target、时限与退出预算；当前 contracts、Worker/D1 和 CLI 尚无这一维度。

| 入口 | 目标接线 | 验收重点 |
| --- | --- | --- |
| 用户 Fast 命令 | 只有实际用户 Off→On 产生一条稳定事实；本机保存结果与计量记录分开反馈 | 多个 Agent 自动读取/恢复/继续/重试均为零新增开启事实，不能每个进程各计一次 |
| Fast/Async 自动恢复 | 读取全局 `settings.json.myPiExtensions` 对应字段，与 `PI_METRICS_CONFIG` 分开；手动编辑与命令共用这一来源 | 开功能不自动开采集；缺失采集配置时不读 Token、不建 outbox、不联网；不迁移既有 metrics 私有配置 |
| 通用 `compaction-duration` | 由 Async 的本地计时/renderer 管理，不调用 `submitMetric` | manual/overflow、能力 Off 及无 UI 本地记录不因此混入远端阶段总体 |
| 原有 Async `Timing.finish` | 保留现有后台/前台阶段终态去重及有界后台投递 | 不直接复用作全部 Agent 通用 UI timer；局部失败不改原生结果 |
| 主/子 Agent 来源 | 在阶段开始时捕获 agentType，由 launcher 或 SDK 会话绑定参数确定，不从任务或角色推断 | 新子 Agent 事件标 subagent，缺失/不能确认的类型为 unknown；有限分类不是账号身份和采集授权 |

### 跨包退出预算（REVIEWING）

Fast与Async在同一次CLI session_shutdown中共用绝对至多一秒的本地提交等待，不能串行各等一秒。SDK执行的owned cleanup直接沿用其host提供的同一绝对deadline；不等网络、不将原Session appendEntry宣称为新增后台IO。

协调协议位于既有Node client，不依赖依赖模块dedupe：从`node:process`取得相同进程对象，以`Symbol.for('@pi/project-metrics/shutdown-budget/v1')`持有version=1及WeakMap（同一公共shutdown事件对象/SDK作用域token → deadline）。原生Runner向两包传同一事件对象，独立module roots仍访问此slot；同步首次发布，后续校验版本/形状，冲突时不等待并标不完整，不覆盖未知slot。新Session/reload生成新token，旧generation只能使用旧预算；仅共享退出时间，不共享功能意图、任务或凭据。

包独立roots、正常/挂起本地提交、忽略abort网络、新旧generation和slot冲突均需真实进程级测试。当前源码仍各自调用drain，本节协议未实现。

### StatsResponseV2 合同

`GET /api/v2/project-stats` 顶层只含 `schemaVersion: 2`、`base`、`byAgentType`。`base` 是原 StatsResponseV1 的完整对象；`byAgentType` 固定包含 `main`、`subagent`、`unknown` 三个键，不因空数据省略。

每个分类项只含：

| 字段 | 精确子结构与边界 |
| --- | --- |
| `completeDays` | 只含 `aggregates`（至多64项）和 `comparisons`（至多 `2 × days` 项） |
| `unlocatedByReceivedDay` | 至多64个阶段 aggregate；表示发生时间缺失，不代表来源或耗时未知 |
| `todayInProgress` | 只含 `receivedAggregates`，至多2项，不计算日环比 |
| `truncated` | 布尔值；上游查询截断或本视图裁剪均置true |

aggregate/comparison 沿用 v1 的精确键和合法数值规则，但只允许两类压缩kind，model/provider恒null，aggregate的eventCount恒0；来源视图按kind统计阶段总体，不复制模型交叉矩阵。模型分组与Fast计数只由base提供。aggregate的unknownCount仍只指耗时未知，byAgentType.unknown指来源未知；空分类数组为空，不伪造零样本。

三个视图与base使用同一查询行快照、asOf、水位、数据集和日期窗口。查询上限20,000行、days范围1..31、响应上限2MiB；严格解析所有键、kind/空字段约束和Token回显。v1回退明确类型统计unavailable，不输出三组假零。正反fixture及最大边界归对应tests维护。

### 当前差距与继续条件

- Fast 偏好候选和 Async 准入仍限制 UI/主 TUI，Dispatcher 仍按旧角色/首次 spawn 继承；现有主入口验证不能证明全部 Agent 已接线。
- `Timing.finish` 当前 DTO 无来源类型。目标压缩事件允许可选 agentType（main/subagent/unknown），Fast 事件不加该字段；缺失类型的旧事件不补字段，保留原 canonical JSON/hash/ACK 幂等含义。非法字段/值仍拒绝，不接受自由文本身份。
- D1 增加可空 agent_type 列并保留既有行、ID、canonical hash、ingest_seq 与水位；缺失类型聚合为 unknown。先以0003建库插入旧数据，再连续应用新增迁移验证兼容；已记录迁移不重复执行，未记录但列已存在等部分状态不明时停止核实。
- `/api/v1/project-stats` 保持原精确字段集合，旧 CLI 可继续读取；新增 `/api/v2/project-stats` 提供独立 Agent 类型分组，覆盖完整日/环比/今日/无发生时间，保留原总体/模型维度。新 CLI 先请求v2，仅404时在同一总五秒截止内回退v1，且v1必须校验成功才显示类型维度 unavailable；鉴权、传输及无效响应不当作版本不支持。四组新旧客户端/服务端组合均需验收。
- 本地验证后，外部发布顺序是 migration → Worker（保留v1并增加v2）→ typed producer/CLI；回滚先停 typed 采集再回滚Worker/client，nullable列和全部事件保持。旧Worker仍可查询原总体，新CLI回退明确无类型维度。真实 CF 部署/迁移另行授权，当前未执行；拒收保留原 envelope/失败证据，再升级后显式 flush --retry-failed，不剥掉类型重发。
- 多进程共用同一配置/目标时，现有 outbox 锁和 event ID 去重继续适用，但其本身不能证明用户开启事实不会重复产生；须在 producer 的真实用户操作边界验证。
- 以 counting/fail-loud sink 验证本地 observer 的 submit=0，以实际命令/终态验证既有 producer 的 0/1 次事件；再做主/子 Agent 真实 CLI/SDK 到本地 Worker/D1/CLI 的 loopback 独立验收。既有 CF 验收不覆盖新来源；真实部署保持未执行。
