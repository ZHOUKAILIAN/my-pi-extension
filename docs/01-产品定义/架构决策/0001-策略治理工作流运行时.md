# 架构决策 0001：采用策略治理的 Workflow Runtime

- 状态：`DECIDED`
- 层级：第一层（L1 架构决策）
- 日期：2026-08-18

## 背景

本产品承载可执行、可审计的工作治理，而不是一组建议模型遵守的 prompt。它需要控制任务如何进入系统、每个 Node 允许哪些角色执行、哪些证据可以交接、Worker 可以使用哪些 Skill 和工具，以及 Run 何时可以推进或完成。

只依赖 prompt 无法强制这些约束。Worker 可能忽略角色说明，主 Agent 可能绕过流程，不受限制的资源发现也会把无关方法和上下文带入任务。

以下三个控制面必须区分：

- Skill Routing：角色可以正常发现和加载哪些 Skill；
- Context Isolation：Worker 可以获得哪些任务材料；
- Capability Isolation：Worker 实际可以读取、写入或执行什么。

## 决策

产品采用策略治理的 Workflow Runtime。

- 顶层 Workflow Extension 拥有用户入口和自己的 Workflow Definition。
- Workflow Definition 拥有 Node Definitions、Stage/Transitions、Transition Guards 和 Acceptance Definition。
- Runtime 根据 Run、Stage、Role 和 Node 解析 Policy，创建受控 Worker Session。
- Worker 只执行当前 Node，通过结构化 Artifact 提交结果；Worker 无权改变 Run 状态或宣布最终完成。
- Runtime 负责 Artifact 合同校验、Guard 执行、状态迁移、checkpoint、恢复和审计。
- Worker 通过最小 Context Capsule 和上游 Artifact 获取任务事实，默认不继承主 Session 完整历史。
- 所有未被当前 Policy 允许的工具和资源默认不可用于该 Worker。
- Runtime 只提供通用治理骨架；方法、项目语境和业务验收分别由 Skill、Project Knowledge 和 Extension 产品规范提供。

Policy 约束当前执行，但不取代 Workflow Definition：前者回答“本次 Node 允许怎样执行”，后者回答“这类任务允许怎样流转和凭什么完成”。

## 产品级安全边界

Skill Routing、Context Capsule 和 Role prompt 只能减少默认暴露面，不能单独作为安全边界。需要安全保证时，必须依靠实际的文件系统、网络和 Capability Isolation，并由运行证据验证。

Policy、Artifact、Guard Record 和 Audit 必须位于 Worker 不能任意改写的控制平面中，并可按版本和 Run 追溯。

## 影响

### 正面影响

- 工作方法可以通过 Artifact 和 Guard 形成可检查、可回放的执行链。
- 多 Agent 方案评审、代码 Review 和验证可以使用确定性门禁。
- Skill、上下文和能力成为显式控制输入，而不是不可见的 prompt 行为。
- Feature、Fix 共享 Runtime，同时各自拥有产品流程和验收语义。

### 成本与风险

- Workflow Definition、Policy、Artifact schema、Guard 和审计协议需要版本化维护。
- 灵活的一次性行为可能需要显式策略扩展或用户决定。
- Pi 工具限制本身不是 OS sandbox；更强隔离必须单独设计和验证。
- L1 产品契约与 L2 当前实现可能阶段性不一致，必须显式记录 drift。

## L2 交接

本 ADR 不决定 Worker 使用 SDK Session、CLI 子进程还是其他承载方式，也不规定具体 CLI 参数、状态枚举、schema、存储协议或重试算法。这些属于第二层实现设计，并可在不改变上述产品保证的前提下演进。

当前实现机制和已知差距见[第二层实现地图](../../02-产品实现/README.md)。

## 备选方案

### 仅使用 Prompt 编排

不采用。它可以引导模型行为，但不能阻止状态越权、能力扩大或不可审计的上下文交接。

### 在每个 Extension 中硬编码全部共享治理

不采用。它会复制 Runtime 规则，使 Feature、Fix 的控制语义和审计方式逐渐分叉。

### 使用外部 Agent Team Runtime 作为控制平面

暂缓。在外部 Runtime 能证明满足本产品的 Policy、Artifact、Guard、隔离、trace 和生命周期要求之前，不替换核心控制面。
