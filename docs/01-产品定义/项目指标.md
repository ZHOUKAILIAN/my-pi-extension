# 个人 Cloudflare 项目指标

状态：`DECIDED`。通过 CLI 向本人 Cloudflare 账号下的 Worker/D1 上报和查询项目指标；不提供网页、多用户账号或共享租户。实现、部署与启用状态见 [L2](../02-产品实现/项目指标-技术设计.md)。

## 1. 账号与采集许可

- 每个人使用自己的 CF 资源，数据归属由目标 Worker/D1 及不可变目标标识确定，不以客户端自报账号作为身份。不采集 Pi 模型登录身份、邮箱、会话 ID、cwd、任务内容或凭据。
- 采集默认关闭，通过显式私有配置启用；`/fast on` 和 `/async-compact on` 不代表允许上报。只接新产生的事件，不扫描历史会话或记录回填。
- 上报和查询走 CLI，不依赖浏览器。Wrangler 登录只用于部署和管理；运行时上报 Token 与查询 Token 分离，不将 CF 管理凭据交给扩展。
- 不自动安装新版本或修改日常 profile；受支持宿主与组合边界由各扩展规范拥有，共用投递器不表示两能力可以在同一会话联合加载。

## 2. 指标及总体

| 指标 | 产生事实与计量 |
| --- | --- |
| Fast 开启次数 | 合法用户命令实际使 requested Off→On，每次一条；重复 On、关闭、初始化、继承和模型切换不计。能力定义见 [Fast](扩展/codex-usage-status-扩展.md) |
| 后台生成耗时 | 每个后台摘要操作调用至 SDK 结果实际结算；生成完成后的 ready 等待不累计 |
| 前台压缩阶段耗时 | 已启用且受支持的 threshold 机会，从本扩展压缩处理 hook 进入至宿主成功/失败 hook；包含候选等待、miss、input preflight 旁路与原生兜底，不含手动或 overflow |

两项阶段耗时的细节由 [Async Compaction §5.4](扩展/async-compaction-扩展.md#54-本地阶段耗时)拥有。它们不是实际用户等待或相对原生策略的省时收益。时间未知不补零，后台与前台总体分开；已有 Token 账目不扩充为项目指标。

## 3. 投递与失败

1. 每条事件在事实发生时捕获稳定全局 ID 和时间，并登记有界后台任务。Fast 命令和压缩 hook 不等待新增打点文件写入、本地待投递提交或网络；后台先持久化私有待投递记录，再发送 POST，不重试模型业务。
2. 相同 ID/相同规范化内容仅计一次；相同 ID 不同内容报冲突，不覆盖原记录。只有同 ID 的明确接受或重复 ACK 才移除待投递记录。
3. 队列、请求体、超时和补报批次有界。断网、超时、拒绝或 ACK 不明保留已提交记录，CLI `flush` 可有界补报；满或本地失败明确标记采集不完整，不删除旧记录腾空间。
4. 正常退出只用统一的有界预算等待本地提交，不等待上传；关闭时停止新传输并取消、隔离在途请求，网络不得延长进程退出。退出预算耗尽、强退或诊断丢失均标采集不完整，不能声称未完成的提交已保存。具体边界及限制见 L2。
5. 待投递事件绑定创建时的 endpoint、目标 namespace 和 live/validation 数据集。切换配置不搬运旧记录，不得发往新账号或新数据集；Token 轮换不改变目标。
6. 采集、诊断与显示失败不改变开关、候选采用、原生返回、费用、取消或冷却。Fast 本地写入失败不伪造已提交记录；Async 从真实终态直接产生事件，不从 UI 或文本推断。

## 4. 私有访问与数据处置

- 写 Token 只能上报，读 Token 只能查聚合；未授权或错权请求不读写业务数据。凭据只在本机私有文件和 CF Secret，不进入 Git、argv、日志或模型上下文；接口不开放 CORS、重定向或公开明细。
- 配置和密钥文件要求私有权限、不跟随不安全路径；目标不符、认证不明或部署结果不明时停止，不猜账号、重建资源或盲目重放。
- 不配置自动删除、TTL 或定时任务。云端事件与未确认队列保留至本人明确清理；validation 数据及证据供复核，不在验收后自动删除。清理必须限定目标、数据集及事件/时间范围，并核对前后计数。
- 读、写 Token 可分别轮换，验证新值可用和旧值被拒绝后更新本机配置；写入维护期间保留队列。泄露优先撤销对应凭据并停用受影响入口，不假称轮换或撤销已成功。

## 5. CLI 统计与环比

默认查询 live，validation 显式单列。结果只代表云端**已接收**数据，不代表所有本地使用。

- 返回服务端截至时间及不可变接收序号水位，所有查询同时受接收时间与水位约束。
- 默认最近七个已结束的完整 UTC 日；额外取得前一基准日。今天另标“进行中”，不参与逐日环比。
- Fast 按去重事件计数；耗时分别按 kind、provider/model 统计已知值均值，附已知样本数和 unknown 数。已知失败/取消耗时仍计入实际消耗；未知不填零。
- 无发生时间的 unknown 按服务端接收窗口单列，不混入发生日均值。迟到补报按发生日修订历史结果，查询截至时间不同，过去日报可变化。
- 环比为 `(本日值−前日值)/前日值`；无样本或前值为零时不可比较，不将趋势解释为因果收益。
- 服务端始终标记 `received_only`，无接收数据或仅有部分覆盖；CLI 同时显示本机同目标的待投递、失败及可知诊断。远端已接收 0 不等于真实使用 0，也不能据本机状态推断其他设备完整性。

## 6. 验收

| 编号 | 条件 |
| --- | --- |
| M1 | 默认不采集；显式启用后仅三类白名单事件，不读取模型身份或历史 |
| M2 | Fast 实际 `on,on,off,on` 捕获两条事实且命令不等待计量 I/O；本地提交在统一退出预算内完成时可核对两条完整记录，预算耗尽标不完整而不延迟业务或假称持久化；重复 ID 不增加计数 |
| M3 | 两项 Async 事件从受支持宿主中的真实生成结算/threshold hook 终态产生，不用手造 DTO 代替接线 |
| M4 | 写/读角色互斥，缺凭据、错目标、非法字段和超额被拒绝，不扩大数据权限 |
| M5 | 本地写入、上传或 ACK 挂起及异常时业务仍返回；截止后逻辑投递有界结束，未确认记录保留且可显式补报，迟到 ACK 不删记录；并发重发、满队列及退出不改变业务或假称完整 |
| M6 | 改配置、改数据集、重启或轮换不会跨账号发送旧队列；新旧 Token 失效流程可验证 |
| M7 | 完整日/今日、基准日、迟到补报、未知时间、零基数及并发水位统计正确，CLI 显示覆盖边界 |
| M8 | 实际远端验证账号/绑定/namespace、权威行、API 与 CLI 一致；旧表和数据保留，失败停机及精确版本回退可核对 |
