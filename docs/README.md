# 五层文档总览

本仓库使用五层模型维护产品、实现、项目默认、GitHub 治理和本地工作现场。分类先看文件负责什么，再看它放在哪里；目录名只是承载结果，不代替责任判断。

## 层级地图

| 层级 | 回答的问题 | 正式承载 | 真理源状态 |
| --- | --- | --- | --- |
| [第一层](01-产品定义/) | 产品是什么、预期语义是什么？ | 产品契约、领域术语、ADR | 已采纳文档是产品意图真理源 |
| [第二层](02-产品实现/) | 当前真实实现了什么？ | `packages/*/src`、`packages/*/test` | 源码和测试是当前运行事实真理源 |
| [第三层](03-项目落地/) | GitHub 仓库如何承载、配置和运行产品？ | monorepo、package、构建与项目配置 | 已采纳项目默认是真理源 |
| [第四层](04-仓库治理/) | 如何协作、验证、交付和关闭工作？ | GitHub 流程、Agent 规则、质量门禁 | 共享治理真理源 |
| [第五层](05-本地开发控制/) | 什么只维持当前本地工作现场？ | ignored 本地材料 | 不是正式真理源 |
| [归档](归档/) | 哪些材料只用于研究、比较或历史追溯？ | 历史选型、评审原文 | 不是活跃规则 |

## 冲突优先级

1. 第一层决定预期产品语义，第二层决定当前运行事实。二者冲突必须报告 drift。
2. 第三层只定义已采纳的仓库默认，不定义产品语义。
3. 第四层约束共享协作和交付，不能被本地说明绕过。
4. 第五层只维持当前工作现场，不能覆盖第一至第四层。
5. 归档只提供背景和证据；结论只有写入相应活跃层后才算被项目采纳。

## 文档状态

| 状态 | 含义 |
| --- | --- |
| `TODO` | 已识别问题，尚未形成契约 |
| `ALIGNING` | 正在收集事实和方案 |
| `REVIEWING` | 等待独立评审或用户决定 |
| `DECIDED` | 已采纳，可作为下游产品或项目输入 |
| `IMPLEMENTING` | 已批准并正在实现 |
| `VERIFIED` | 已有对应运行验证证据 |
| `BLOCKED` | 缺少决策、事实或验证，不能继续 |

只有 `DECIDED`、`IMPLEMENTING`、`VERIFIED` 中明确标注为规范性内容的部分可以作为正式意图。当前行为是否已实现，仍需读取第二层。

## 写回路由

- 产品行为、领域语义、扩展边界或架构决策：写第一层。
- 源码、测试、当前技术事实：写第二层。
- package、目录、构建、安装或项目模型策略：写第三层。
- GitHub、Agent、review、验证和交付规则：写第四层。
- 临时任务状态、trace、handoff、session 草稿：留在第五层本地。
- 研究、方案比较、外部背景和评审原文：写归档。

详细阅读顺序见 [文档地图](03-项目落地/文档地图.md)。Agent 执行规则见根目录 [`AGENTS.md`](../AGENTS.md)。
